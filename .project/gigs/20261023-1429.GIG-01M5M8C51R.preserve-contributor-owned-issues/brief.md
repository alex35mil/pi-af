# Brief

Preserve contributor-owned issues during workflow adoption

Adopting a contributor’s issue currently binds the original issue, then replaces its description when publishing the accepted plan. Preserve the contributor’s request while managing work within that same issue.

- Explicitly distinguish workflow-owned from contributor-owned content at intake; Project membership does not establish ownership.
- Preserve contributor-owned titles and descriptions.
- Publish and update the accepted plan in one identified workflow-owned comment, with safe recovery after uncertain publication.
- Keep accepted local artifacts authoritative and retain normal planning, review, approved delivery, and tracker metadata management.
- Resolve requirements from issue discussion with the maintainer; contributor comments do not automatically authorize scope changes.
- Implement this at the shared publication boundary, updating affected consumers, guidance, and tests.
- Keep existing description publication for workflow-owned issues. Do not create duplicate tracking issues.
