# Brief

Make tracker issues concise while preserving detailed plans

Optimize how workflow issues and pull-request bodies are presented so the visible, readable part is easy for a human to consume and gives full but concise context of the entry.

For tracker issues, decide between the brief alone or the brief with plan highlights. Collapse the remaining plan details under `<details>` on GitHub and investigate an equivalent presentation in Linear.

For pull-request bodies, keep the visible overview concise and collapse supporting detail, including verification, under `<details>` on GitHub.
