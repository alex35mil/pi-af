# Incoming PR command and checkout tool

Registers `/pr <GitHub PR URL or #NN>` and routes the explicit selection to the `pr` skill as a follow-up message. The command itself makes no provider call, branch change or mutation grant. Empty input displays usage.

Also registers the separate native deferred checkout tools listed in [Workflow tools](../../references/tools.md#incoming-prs), each with `reference`, actual configured PR-get `evidence`, and only that operation’s additional inputs. `operations.ts` owns the shared name map used by registration and generated guidance. No operation selector is passed. `checkout.ts` owns routing/inspection and parent verification, `state.ts` owns validated original/current/progress facts, `worktree.ts` reads native Git state, `rebase.ts` owns target observation/standard rebase/approved-resolution continuation and immediate pinned-lease publication, and `git.ts` owns safe direct Git execution. The tool derives exact paths/URLs/revisions, preserves unexpected work and compares parent state on success/failure. It returns paths, revision, merge-base, phase validation and diff state, with complete private evidence behind bounded output. Rebase inputs add exact observed target/source SHAs; continuation adds exact approved resolution paths. Rebase approval covers replacement commits and immediate push with explicit SHA-pinned `--force-with-lease`, not later fixes/testing. Failed/uncertain publication is reconciled against the actual contributor ref without a new lease or blind retry. `fixes.ts` owns approved exact-path additive commit and separately approved normal publication with managed baseline/recovery; `cleanup.ts` owns verified post-merge retirement/removal and inspection after removal. GitHub merge stays in the shared forge operation, not this Git tool. No arbitrary command/path overrides, contributor-code execution or unapproved commits/review/merge mutations. See [checkout tooling](../../references/pr/checkout.md) for independent approvals and refusal handling. The agent never reconstructs these operations in Bash; there is no manual fallback.

`git.ts` supplies one validated-identity SSH URL builder for all GitHub fetch, remote-tip observation and push operations: `git@github.com:<owner>/<repo>.git`. Existing trusted SSH authentication is inherited; the tool configures no HTTPS credentials and changes no parent/global Git configuration. Saved completed-but-unpublished records contain no transport URL, so approved `publish_incoming_pr_rebase` recovery uses SSH with the same result and original lease without recreating the checkout, rerunning rebase or migrating state.

The [Project procedure](../../references/pr/project.md) keeps maintainer-controlled Backlog/Todo -> In Review until confirmed Done/Canceled; fork-only [setup automation](../../references/pr/automation.md) adds membership without field resets. [Shipping](../../references/pr/shipping.md) uses the one shared repository merge operation and includes safe local cleanup in the exact ship/merge set, preserving parent state, contributor branches and private evidence.

The [PR skill](../../skills/pr/SKILL.md) and [incoming PR procedure](../../references/pr/incoming.md) own private inspection, exact-revision approval, contributor access, and execution/merge boundaries. Configuration and identity belong to `integrations/forge/github/incoming-pr-context.ts`; independent review belongs to `review/pull-request.ts`. This is not Epic/Task/Gig initialization or submission.
